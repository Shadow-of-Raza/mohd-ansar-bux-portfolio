## 1. Overview

`HOME-00` is the hero section of the portfolio homepage (`/`). It delivers the first visual and editorial impression for Mohd Ansar Bux — Full-Stack Software Engineer.

### Content & Functional Elements Built

1. **Availability Badge:** Active status badge (`Open to freelance & full-time roles`) with an animated pulsing dot indicator (`bg-royal text-white`).
2. **Eyebrow:** Section metadata (`Full-Stack Software Engineer — Indore, India`) in `font-label` Alegreya SC.
3. **Hero Title (`h1`):** Prominent uppercase name (`MOHD ANSAR BUX`) set in Archivo Black (`font-display`).
4. **Value Proposition Headline:** Sub-headline statement (`Architecting digital products that *ship*`) formatted via `renderAccent()` with the emphasised word in Averia Serif Libre italic (`font-accent text-electric-300`).
5. **Introduction Copy:** Core technical summary paragraph in Abhaya Libre (`font-body text-fg-muted`).
6. **Action CTAs:**
   - Primary: `View projects` (`LinkButton` variant `primary` in `bg-electric` with hover arrow nudge).
   - Secondary: `Contact me` (`LinkButton` variant `secondary` with hairline border).
7. **3D Visual Poster & Ambient Lighting:**
   - High-resolution cinematic poster (`public/hero/hero-poster.webp`) loaded via `next/image` with `priority={true}` for optimal LCP.
   - Ambient radial glow (`hero-glow` utility, `royal` gradient with max 32% opacity per `03 §8`).
8. **Scroll Cue (`ScrollCue`):**
   - Thin-line indicator with a continuous CSS drop runner animation.
   - Automatically fades out when scrolling down (`window.scrollY > 30`).
   - Supports `prefers-reduced-motion: reduce` by replacing the loop animation with a static subtle line.

## 3. Deviations from the Docs & Why

- **Static poster in place of WebGL:** Per the Phase plan (`02 §9` and `SKILL.md`), 3D WebGL / Three.js / R3F is scheduled for **Phase 7**. During Phase 4, the hero is built static using the authentic WebP poster (`/hero/hero-poster.webp`) and ambient radial lighting (`hero-glow`).
- **No deviations:** All color tokens, typography scales, presence rules, and accessibility constraints strictly match `docs/context/`.
