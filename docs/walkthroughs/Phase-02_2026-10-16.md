## 1. Overview

Phase 2 establishes the complete JSON-driven data foundation for the portfolio. All personal copy and portfolio data live strictly in `src/data/*.json`, validated at build time via Zod 4 schemas, loaded through server-only modules with presence-rule filtering, and linked through derived relational mappings. Dynamic metadata endpoints (`/sitemap.xml` and `/robots.txt`) and a full prebuild validation script (`pnpm validate:data`) ensure end-to-end type safety and content integrity.

## 2. Files Created & Modified

### Core Utilities

- [`src/lib/utils/has-content.ts`](../../src/lib/utils/has-content.ts):
  - `hasContent(value)`: Recursively checks whether a value has user-facing content, ignoring flags (`visible`, `featured`, `order`, `confidential`) per `05 §4.1` & `§7.1`.
  - `nonEmpty(list)`: Returns the array if it contains items, otherwise `null`.
- [`src/lib/utils/dates.ts`](../../src/lib/utils/dates.ts):
  - `formatYearMonth(ym)`: Formats `YYYY-MM` into readable strings (e.g., `"Jan 2025"`).
  - `calculateDuration(start, end)`: Calculates duration in years and months (e.g., `"1 yr 4 mos"`), treating `null`/`undefined` as present.
  - `calculateTotalExperience(intervals)`: Merges overlapping employment intervals and calculates total cumulative experience without double counting.
  - `compareDatesDesc(a, b)`: Compares dates in descending order with `null` (present) sorting first.

### Schemas & Types

- [`src/lib/data/schemas.ts`](../../src/lib/data/schemas.ts):
  - Starts with `import "server-only"`.
  - Zod 4 schemas with `.prefault({})` for nested defaults, `z.url()`, `z.email()`, and inferred TypeScript types for all 8 content files:
    - `SiteSchema` / `type Site`: Identity, availability, hero copy, socials, and site SEO.
    - `ProfileSchema` / `type Profile`: About copy, bio, portrait, resume, gallery, interests, hobbies, and basic info.
    - `ServicesFileSchema` / `type Service`: Service catalogue with deliverables, process, FAQs, and technology links.
    - `ExperienceFileSchema` / `type ExperienceCompany` / `type ExperienceRole`: Companies and roles with computed durations, achievements, skills, and linked projects.
    - `EducationFileSchema` / `type Education`: Academic degrees, institutions, coursework, and scores.
    - `ProjectsFileSchema` / `type Project`: Project write-ups, tech stack references, covers, galleries, and live/repo links.
    - `SkillsFileSchema` / `type Skill` / `type SkillCategory`: Categorised skills catalogue (usage is computed, not stored).
    - `ContactSchema` / `type Contact`: Contact details, response time, and form toggles.
    - Shared: `ImageSchema`, `SeoSchema`, `PageCopy`, `HomeCopy`.

### Loaders & Availability

- [`src/lib/data/loaders.ts`](../../src/lib/data/loaders.ts):
  - Starts with `import "server-only"`.
  - Parses each file once at module level (throws at build time on schema mismatch).
  - Filters out `visible === false` items, sorts per `05 §5`, and slices previews by `home.limit`.
  - Presence rule: returns `null` when a collection has no visible items (`getServices()`, `getExperience()`, `getEducation()`, `getProjects()`, `getSkills()`, `getProfile()`, `getContact()`).
  - Exports `getProjectBySlug(slug)`.
- [`src/lib/data/availability.ts`](../../src/lib/data/availability.ts):
  - Starts with `import "server-only"`.
  - Single source of truth for page existence (`ROUTES`).
  - `getNavItems()`: Dynamically returns available navigation links (`Home`, `About`, `Services`, `Experience`, `Education`, `Projects`, `Skills`), automatically excluding pages whose loaders return `null`.
  - `hasContactPage()`: Checks if contact route is active.

### Derived Relations

- [`src/lib/data/relations.ts`](../../src/lib/data/relations.ts):
  - Starts with `import "server-only"`.
  - Build-time cross-file relational computations returned as plain serialisable objects:
    - `getSkillMap()` & `getSkillById(id)`: Direct skill lookup.
    - `getSkillUsage()`: Record mapping each skill to referencing projects (`{ slug, title }`), companies, and services.
    - `getProjectsBySkill()`: Groups visible projects by skill for `/projects` filtering.
    - `getServiceOptions()`: Service titles + `otherOptionLabel` for contact form select input.
    - `getAdjacentProjects(slug)`: Previous and next project links for project detail navigation (`PD-06`).
    - `getTotalExperienceDuration()`: Cumulative career experience string derived from role dates.

### SEO Endpoints

- [`src/app/sitemap.ts`](../../src/app/sitemap.ts):
  - Generates dynamic XML sitemap linking all routes from `getNavItems()` plus individual visible project slugs.
- [`src/app/robots.ts`](../../src/app/robots.ts):
  - Generates `robots.txt` pointing to `/sitemap.xml` and disallowing `/style-guide` and `/api/`.

### Validation & Config

- [`scripts/validate-data.ts`](../../scripts/validate-data.ts):
  - Full prebuild data validator covering all 6 fatal errors and 4 non-fatal warnings from `05 §8`:
    1. Schema validation against Zod definitions for all 8 files.
    2. Duplicate `id` and `slug` checks within each file.
    3. Cross-file referential integrity (`projects` → `skills`, `experience` → `skills`/`projects`, `services` → `skills`, `skills` → `categories`).
    4. Existence of local assets in `public/` (logos, posters, portraits, gallery images, resumes, skill icons).
    5. Date formatting and chronological validity (`end` ≥ `start`).
    6. Open-source projects have valid GitHub URLs.
    7. Warnings for excessive featured items, thin project cards, empty non-decorative `alt` text, and unused skills.

## 3. Presence Rule & "Done When" Verification

Per `02 §9`, Phase 2 is done when:

> _"Removing a JSON array hides its page, nav link and sitemap entry. Write the validator checks from 05 §8."_

### Verification Tests:

1. **Full Data State:**
   - `getNavItems()` returns: `Home`, `About`, `Services`, `Experience`, `Education`, `Projects`, `Skills`.
   - `/sitemap.xml` dynamically emits all 7 base routes + 2 project detail routes (`/projects/enterprise-analytics-platform`, `/projects/open-source-api-toolkit`).
2. **Empty Array State:**
   - When a collection's `items` array is empty (or all items set to `visible: false`), the corresponding loader returns `null`.
   - `getNavItems()` immediately drops that route from the header, mobile menu, and footer HTML sitemap.
   - `/sitemap.xml` excludes that route and any nested child slugs.
3. **Live Endpoint Test:**
   - Dev server GET `/robots.txt` returned **HTTP 200** with valid sitemap directive.
   - Dev server GET `/sitemap.xml` returned **HTTP 200** with complete `<urlset>`.
